# NBA 球员信息可视化网站 —— 需求分析

> 版本：v1.0（2026-09-06）｜ 定位：软件开发实践大作业的**增值交付物**（答辩现场演示 + 加分项）

---

## 1. 项目概述

在第 1 轮交付（Python 控制台交互系统：7 模块、14\~22 张统计图）基础上，将分析结果**升级为浏览器端的可视化网站**：

- **复用而非重写**：清洗 / 生涯表 / 转会检测 / KMeans 聚类全部沿用现有 Python 模块，只把"PNG + 控制台"的输出端换成"JSON 接口 + 网页渲染"；
- **零构建纯静态**：原生 HTML/CSS/JS（ES Modules） + 本地打包 ECharts，无 CDN、无框架、无编译链，断网可演示；
- **为技术路线预留接口**：数据层按 REST 风格设计 JSON 接口契约，将来可由 C++ 后端（Drogon）替换为 HTTP API，前端零改动。

## 2. 用户与使用场景

| 用户 | 场景 | 诉求 |
|---|---|---|
| 答辩评委/课程老师 | 现场打开网页浏览 | 打开即用、交互直观、数据可信 |
| 组员（童诗轩/钱于畅） | 复盘与二次讲解 | 与报告口径一致，可对照源代码 |
| 好奇同学 | 随意点击球星 | 搜索友好、加载快、不落俗套 |

## 3. 功能需求

| 编号 | 模块 | 功能 | 优先级 |
|---|---|---|---|
| F1 | 首页 | 数据概览卡 + 全量球员列表（3919 人，默认按生涯总得分降序；支持排序 / 分页 / 位置筛选） | P0 |
| F2 | 首页 | 即时搜索框：模糊匹配（支持中文名 / 英文子串，如 `iverson`→艾弗森），巨星排前 | P0 |
| F3 | 首页 | 30 位名人堂快捷入口（中文名 + 头像缩略图） | P0 |
| F4 | 球员详情 | 汇总卡（位置/身高/体重/赛季起止/总得分） | P0 |
| F5 | 球员详情 | 生涯走势折线图：4 指标切换（得分/篮板/助攻/PER），转会赛季红色竖线，悬停/缩放 | P0 |
| F6 | 球员详情 | 7 维能力雷达图：相对联盟平均（金线 = 1.0 倍基准） | P0 |
| F7 | 球员详情 | 转会卡片（多次转会 tab 切换 + 转会前后对比 + 变化率标注） | P0 |
| F8 | 球员详情 | 聚类归属展示（"簇0 顶级得分手"，附该簇代表球员） | P0 |
| F9 | 双星对比 | 双选择器 + 双雷达（按两人较大值归一化）+ 差值表 + 自动点评（差值 >15% 判定明显差距） | P0 |
| F10 | 总览 | 4 张统计表（整体/位置/年代/相关性）转 HTML 表格 + 图 1~10 嵌入 + 聚类/预测算法对比表 | P0 |
| F11 | 照片集成 | `img` 字段预留：检测到照片自动显示，缺失用 SVG 占位不碎图 | P1 |

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首页索引 773KB 加载 <1s；详情页按需懒加载 `career_{slug}.json`（人均几 KB）；总资源 ≤5MB |
| 兼容性 | 现代浏览器（Chrome/Edge/Firefox）；**纯静态零依赖**——ECharts 本地打包，无 CDN，离线可用 |
| 可维护性 | 前后端分离思想：`web/generate.py`（或 web_generate.py）是唯一数据出口；重跑即全量更新；接口契约字段稳定 |
| 口径一致 | 所有数字与分析系统同源（场均 = 累计/出场；转会检测 = TOT 行；聚类 = K=5 七特征标准化，样本 2006 人，轮廓 0.275） |
| 部署 | 三选一：本地 `python -m http.server 8080` / GitHub Pages / 云服务器 `http://IP:8080`（免备案端口限制） |

### 5.2 数据流（系统视图）

```
【Python 端 · 一次运行生成（离线预计算）】              【浏览器端 · 运行时】

    │                                                        │
    ├─ data_clean   清洗·TOT去重·位置身高规范化               │  fetch ① players.json
    ├─ data_analyze.build_career_df  → 生涯表(3919人) ──┐     │  fetch ② career_{id}.json（懒加载）
    ├─ data_mining  K=5 七特征聚类 ────────────────┐  │     │  fetch ③ clusters.json / stats.json
    ├─ data_profile.transfer_info  转会检测 ──┐    │  │     │
    └─ web_generate.py ──────────────────────┴────┴─────┼──►  web/data/*.json（接口契约）
         照片检测 img字段 → web/images/players/          │
                                                         ▼
                    web/ 静态目录 ── 托管：http.server / GitHub Pages / 云服务器:8080
                                                         │

                                           ECharts 本地渲染 + 原生 JS 交互

```

### 5.3 页面流转时序（详情页）

```
用户点击列表项 → player.html?id=michael_jordan
  ├─ ① 解析 URL 参数 id
  ├─ ② fetch career_{id}.json ──→ 不存在则显示"未找到"占位
  ├─ ③ 渲染汇总卡 / 折线图（ECharts） / 雷达图 / 转会卡片 / 聚类归属
  ├─ ④ 转会卡片：>1 次转会 → tab 切换；变化率 = (后-前)/|前|×100%
  └─ ⑤ "与他对比" → compare.html?p1=michael_jordan

用户加载双星对比页 → 双 fetch 两个 career JSON → 双雷达（较大值归一化）→
                 差值表 → 点评规则：|差值比例| > 15% 判定明显差距（最多取前 3 条）
```

## 6. 数据模型（接口契约摘要）

| 资源 | 路径 | 内容 |
|---|---|---|
| 球员索引 | `data/players.json` | 3919 人：id/name/name_cn/pos/身高体重/赛季起止/总分/场均/簇号/img |
| 球员详情 | `data/career_{id}.json` | 汇总 + 逐年（场均口径）+ 雷达（7 维倍率 + 联盟基准）+ 转会(前后+变化率) + 峰值 + 簇号 |
| 聚类结果 | `data/clusters.json` | K=5：各簇质心/规模/代表球员/语义标签 + KMeans·GMM·DBSCAN 对比 |
| 总览统计 | `data/stats.json` | 数据卡 + 4 张统计表（整体/位置/年代/相关性） |
| 名人堂 | `data/famous.json` | 30 位：id/中英文名/img |

> 契约演进：C++ 后端阶段，上述路径直接映射为 `GET /api/players`、`GET /api/players/{id}/career` 等 REST 路由，前端只改 `api.js` 的 base 地址。
